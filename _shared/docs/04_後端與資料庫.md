## 1. Firestore

結構維持「前綴分學期」（`{學期}-progress`），沒有改成子集合。理由：

- 安全規則會變複雜（子集合要另寫一層 match，還要處理 collectionGroup）
- 教師端所有查詢都要改成 collectionGroup，成本高
- 前綴分法有個容易被忽略的優點：**學期結束後整包封存或刪除很單純**

集合清單見 [03 資料格式規格](03_資料格式規格.md)。

### 2026-07 的四項整理

| 項目 | 處理 |
|---|---|
| 名冊兩份（同一批學生） | 合併成跨學期共用的 `roster` |
| 闖關紀錄命名不一致且藏在 `artifacts/…` | 併進 `{學期}-progress` 的 `history` |
| `{學期}-grades` 規則有、程式沒用 | 刪除 |
| appId 散了 5 組 | ⚠️ **尚未收斂**，見 [06 上線檢查表](06_上線檢查表.md) |

安全規則的正本是 `shared/firestore.rules`。
**一個 Firebase 專案只有一份規則，發佈時整份覆蓋** ——
不要只貼其中一段，否則另一個學期會被鎖死。

## 2. GAS 檔案備份（`shared/filebackup.gs`）

一支部署服務兩學期兩種檔案。

### 資料夾規則

```
<根> / 學期 / 單元 / 班級 / 座號 / 檔名

<根>/11501/thinking/801/05/03.png     運算思維通關截圖
<根>/11501/scratch/801/05/03.sb3      Scratch 作品（AI 批改 2⭐ 以上才上傳）
```

舊版是「截圖一個根、作品一個根」，各自少一層「單元」，
所以必須各開一支 Apps Script 專案、`TERM` 還得寫死 ——
腳本註解自己就寫著「本學期請另外開一個專案部署」，這正是漂移的來源。
**多包一層單元之後，一支部署就夠了。**

### 三道檢查

| 檢查 | 作用 |
|---|---|
| `checkTerm()` | 學期白名單（`ALLOWED_TERMS`），亂傳會被擋下並回報錯誤 |
| `checkKey()` | 請求要帶 `key`，與指令碼屬性的 `UPLOAD_KEY` 比對 |
| `checkSize()` | 單檔上限 15 MB |

前端對應：`config.js` 的 `GAS_UPLOAD_URL` 與 `GAS_UPLOAD_KEY`，**兩學期填同一個值**。
上傳 payload 必須帶 `term` 與 `key`。

### 部署

1. Apps Script 專案貼上 `shared/filebackup.gs`
2. 專案設定 → 指令碼屬性 → 新增 `UPLOAD_KEY`（值同 `config.js` 的 `GAS_UPLOAD_KEY`）
3. 部署 → 網頁應用程式，執行身分「我自己」／存取權「任何人」
4. **用瀏覽器直接打開部署網址**，`doGet` 會列出根資料夾名稱、兩學期的資料夾連結、
   `keyRequired` 是否為 `true` —— 打開看到的路徑對不對，比等學生上傳失敗才發現好
5. 選用：手動執行 `createAllSeatFolders("11501")` 預建座號資料夾

> 改完一定要**重新部署**（管理部署作業 → 編輯 → 版本選「新版本」），
> 用「編輯現有部署」網址才不會變，前端就不用改。

## 3. Colab AI 批改後端（`shared/backend.ipynb`）

### 只有一本

`11501_backend.ipynb` 已刪除。原因：兩本寫死同一個 ngrok 靜態網域，
免費版一帳號只有一個，誰後啟動誰佔走。

前端呼叫一律帶 `term`（用 `CONFIG.TERM`，不要寫死）：

| 前端送出 | 後端讀寫 |
|---|---|
| `term=11501` | `11501-grader` / `11501-scratch-submissions` |
| `term=11502` | `11502-grader` / `11502-scratch-submissions` |

沒帶 `term` 時退回 `GRADER_TERM`（預設 `11501`），讓舊頁面照常運作。

### Firestore 存取改用匿名登入

後端原本用「未登入的 REST（只帶 api_key）」，安全規則因此必須開成 `if true`。
現在會先匿名登入取得 `idToken`，每次請求帶 `Authorization: Bearer`，
規則就能收成 `if isSignedIn()`。

| 函式 | 作用 |
|---|---|
| `_fs_signin()` | 匿名登入（idToken 約 1 小時） |
| `_fs_refresh()` | 用 refreshToken 續期，長時間上課不會中途失效 |
| `_fs_token()` | 取可用權杖；失敗回空字串，退回未登入模式而不是整個掛掉 |
| `_fs_http()` | 自動帶權杖；401/403 清掉重登一次再試 |

⚠️ 前提：Firebase Console → Authentication → 登入方式，**「匿名」必須啟用**。

### Colab Secrets（6 個）

| Secret | 用途 | 必要性 |
|---|---|---|
| `NGROK_TOKEN` | 啟動 ngrok 固定網域 | **必要** |
| `GEMINI_API_KEY_1` | AI 批改 | **必要** |
| `GEMINI_API_KEY_2` | 第二把金鑰，額度用完自動輪替 | 選用 |
| `CLASS_PASSCODE` | 上學期班級密碼 | 選用（留空＝不檢查） |
| `CLASS_PASSCODE2` | 下學期班級密碼 | 選用 |
| `NGROK_API_KEY` | 網域被別的 runtime 佔住時自動清除 | 選用 |

> 匿名登入**沒有新增任何 Secret**，用的是 `config.js` 裡那把公開的 Firebase `apiKey`。
> `CLASS_PASSCODE` 對應的 `CLASS_PASS` 明寫在 `config.js`，學生看得到，別當成真正的防護。

### 怎麼確認 Colab 跑的是最新版

後端 `/api/health` 回報 `features` 清單，前端比對 `config.js` 的 `BACKEND_FEATURES`。

- 新增端點時：後端 `features` 加一個名稱 → 兩支 `config.js` 的 `BACKEND_FEATURES` 加同一個
- `SERVER_VERSION` 純顯示，前端不做判斷
- 少了任一項，教師端會主動提示你去 Colab 重跑

**上課前開教師端工具列的「🩺 狀態檢查」**（`shared/status.html`），一次確認五件事：
後端版本、Gemini 金鑰、排隊機制、兩學期批改標準是否分開、Firestore 規則是否生效。

### 換 notebook 的正確做法

Colab 上跑的多半是雲端硬碟裡的**副本**。只重跑舊副本，改動不會生效。

- 換版：Colab → 檔案 → 上傳筆記本 → 選 `shared/backend.ipynb`
- 或更好：Colab → 檔案 → 開啟筆記本 → GitHub → 選 repo 的 `shared/backend.ipynb`，
  這樣永遠跑到最新版，不會有副本走鐘的問題
