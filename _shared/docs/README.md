## 這套系統是什麼

八年級資訊科技課程的闖關學習網站，一套程式碼服務上下兩個學期。

```
course_115/
├── _shared/            ★ 唯一可以編輯的共用來源（程式與文件都在這）
│   └── docs/           ★ 你正在看的這幾份
├── sync_shared.py         把 _shared/ 複製進兩個 repo 的 shared/
├── course_11501/       上學期網站（repo → GitHub Pages）
│   ├── shared/            由 sync 產生，不要手改
│   ├── content/           這學期教什麼（章節、題庫）
│   └── config.js          這學期的設定（唯一該學期專屬的程式檔）
└── course_11502/       下學期網站，結構完全對稱
```

**最重要的一條規則：改共用檔請改 `_shared/`，改完執行 `python sync_shared.py`。**
直接改 `course_115xx/shared/` 裡的副本會在下次同步時被蓋掉，而且 `push.bat` 會擋下推送。

## 三個最容易踩到的地雷

1. **改了共用檔卻忘記同步** —— `push.bat` 會擋下來，跑 `python sync_shared.py` 就好。
2. **Colab 跑到舊版 notebook** —— 正本是 `shared/backend.ipynb`，不是雲端硬碟裡的舊副本。
   教師端的「🩺 狀態檢查」會直接告訴你跑的是哪一版。
3. **只改一個學期** —— 現在幾乎所有東西都是共用的，改一次兩邊都會變。
   反過來說，如果你發現「只有一個學期需要改」，那八成該改的是 `config.js` 或 `content/`。
