# 08 · 關卡製作範本

> **2-1-1「平行的正方形」是範本。**
> 後面每一關照它的樣子做，不必重新想結構。
> `levelpage.test.js` 有一段會拿 2-1-1 當「完整關卡」的守門員 ——
> 它缺欄位就會紅字，所以範本不會在沒人發現的情況下爛掉。

---

## 一關長什麼樣子

資料全部寫在 `11502/content/blocks.js` 的 `BLOCK_LEVELS['關卡代號']` 裡。
`11502/level.html` 讀它，**有什麼資料就出現哪些步驟**：

| 步驟 | 出現條件 | 資料欄位 |
|---|---|---|
| 🎬 情境解說 | 一定有 | `task`、`scene` |
| 🍔 套餐工廠 | `combo: true` | （內容在 `shared/combo.js`） |
| 🔍 問題分析 | 有 `analysis` | `analysis.qs`、`analysis.write` |
| 📐 推導 | 有 `derive` | `derive` |
| 🧠 概念檢測 | `quiz` 至少 5 題 | `quiz` |
| 🧩 程式拼圖 | 有 `goal` | `palette`、`goal`、`alts`、`loose` |
| 🚀 實作測試 | 一定有 | （共用的上傳評分站） |

> ⚠️ **沒有資料的步驟直接不出現**，不要留一個空殼。
> 例如第 5 關（排隊比高矮）課本用的是圖解，本來就沒有拼圖。

## ① 情境解說 `scene`

```js
task: '（一句話：這一關要做出什麼）',
scene: {
  why:   '為什麼要學這個。<span class="hl">重點畫螢光筆</span>。',
  shots: ['按下綠旗之後會看到…', '接著…', '最後…'],   // 至少 3 句
  pre:   '先備知識：七上「繪圖篇」…'
}
```

**規矩**

- `why` **從學生最熟的東西開始**。2-1-1 的順序是：速食店套餐 → 學校處室 → 電腦主機，
  離他的生活愈來愈遠。直接從「校務行政系統」開場的話，那對國中生也只是一個名詞
- 螢光筆（`<span class="hl">`）**一段最多兩三處**。畫太多等於沒畫
- ⚠️ **不可以洩漏積木答案**（「右轉 90 度」「重複 4 次」）。
  情境要讓人看懂目標，不是看到解法 —— 測試會掃

## ② 問題分析 `analysis`

課本把題目拆成幾個問題，這裡一題一題走完。

```js
analysis: {
  intro: '課本把這個題目拆成五個問題。先自己想一遍…',
  qs: [
    { q: '如何畫出一個正方形？',
      forbid: ['移動 30 點', '右轉 90'],        // AI 引導不可以說出口的
      keys: [                                    // 這一問希望學生講到什麼
        { name: '畫完一條邊之後要轉彎', any: ['轉','轉彎','轉角','旋轉'] },
        { name: '做四次',               any: ['四','4'] }
      ],
      asks: [                                    // 小判斷題，3 題抽 1
        { q: '畫一個正方形，最小的重複單位是什麼？',
          options: ['走一條邊，然後轉一個角', '走四條邊', '轉一整圈', '把筆放下'],
          answer: 0, why: '一條邊配一個角，做四次就回到起點。' },
        …再兩題…
      ],
      hint: '走一條邊、轉一次角，做四次就回到起點。…' },

    { q: '哪一段程式是一直重複在做的？',
      pick: {                                    // 這一關真正的判斷，值得動手圈
        prompt: '點選哪幾行合起來才是「畫一個正方形」：',
        lines: ['下筆', '重複 4 次（…）', '停筆', '移動 60 點'],
        answer: [0, 1, 2],
        ok: '就是這三行。…',
        tooMany: '「移動 60 點」不是畫正方形的一部分 ——…',
        tooFew: '再想想：少了那一行，筆還放得下來嗎？'
      },
      hint: '…' }
  ],
  write: {                                       // 整段的收尾
    q: '用你自己的話說：把「畫正方形」包成副程式，好處是什麼？',
    min: 15,
    keys: [ … ],                                 // 判定用（講到任一個就過）
    hintText: '想想看兩件事：不包起來的話同樣的積木要拼幾遍？…',
    forbid: [ … ],
    sample: '課本列了三點 —— …'                  // 寫完才會顯示
  }
}
```

**規矩**

- **每一問都要有 `keys`** —— 沒有的話「問問看」（AI 引導）掛不上去，
  因為 AI 不知道要往哪個方向引導
- 每一問要嘛有 `pick`（圈選題），要嘛有 `asks`（3 題抽 1）。
  ⚠️ 都沒有的話會退回「寫一句」，而那**擋不住把提示貼上來**
- `asks` 每題 **4 個選項**，答對時要說得出「為什麼是它」（`why`）。
  選項會洗牌，不必擔心正解排在第一個
- ⚠️ **四個選項的長度要相近**（字數差 ≤ 4，正解不可以比別人長 2 字以上）。
  第一版每一題的正解都是描述最詳細、字最多的那個 ——
  學生用「選最長的」就能過關，學到的是猜題技巧不是這一關的概念。
  測試會比對長度
- ⚠️ **錯的選項要是「像樣的誤解」**，不是明顯亂寫的。
  「課本規定」「這樣比較快」這種一看就知道是湊數的選項等於少一個干擾項 ——
  四選一變成三選一。這件事**沒辦法自動測，只能自己念一遍**：
  *如果我完全不懂這一關，這四個看起來會不會都有道理？*
- ⚠️ **一整關只放一題 `pick`**。五問全部要作答會變成問卷 ——
  只有「這一關真正的判斷」值得動手圈
- `write.hintText` 只能講「往哪裡想」，**不可以把 `keys` 的名稱寫進去** ——
  那就是答案

### ⚠️ `keys` 的 `name` 和 `any` 要對得上

`name` 不是給你看的標籤 —— 它會原封不動寫進 AI 的提示詞（「★ 還缺：…」），
AI 就照那句話決定要問什麼。

> 2026-08-07 實測：第一項原本叫「走一段再轉」，九則回覆有八則在問
> 「角色要怎麼走才能畫出第一條邊？」—— 模型抓住了「走」。
> 可是學生答「往前走」並不會命中 `any`（裡面全是「轉」的同義詞），
> 於是下一輪還是問同一件事，學生繞不出去。
>
> **判定標準在 `any`，引導方向在 `name`** —— 這兩個對不上，
> AI 就會很努力地把學生帶去一個不算分的地方。

## ③ 概念檢測 `quiz`

**至少 5 題**（建議 6 題，每次抽 5）。開放式作答，判「有沒有講到這幾個概念」。

```js
quiz: [
  { q: '要畫六個一樣的正方形。如果<b>不</b>包成副程式，你得做什麼？那樣有什麼不好？',
    need: [
      { name: '同一段要拼很多遍',
        any: ['六遍','六次','很多次','好幾','重複','一直','再拼','複製'] },
      { name: '要改的時候很麻煩',
        any: ['改','麻煩','累','花時間','都要動','漏'] }
    ],
    full: 1,                                     // 講到幾群算「完全懂」
    avoid: [{ name: '以為問題出在程式碼太長',    // 常見誤解，只降一級不歸零
              any: ['太長','很長','字太多'],
              why: '長度不是重點 —— 一段很長但只做一次的程式，不必包。' }],
    min: 10,
    ref: 'write',                                // 提示要回頭引哪一段
    hint: '想想看：沒有副程式的話，第二個正方形的積木要從哪裡來？',
    why:  '模組化的判斷標準是「這一段會重複做」，不是「這一段很長」。' }
]
```

**規矩（測試都會盯）**

1. 每個概念**至少 3 種說法** —— 只收一種寫法等於在考默寫
2. 單一核心概念的題目設 `full: 1` —— 寧可放過
3. `min` 不超過 14 字。**只要講到任何一個概念，字數限制就不套用**
4. `why` 要講**概念**，不要只講「你錯了」
5. ⚠️ **單獨一個字的同義詞要很小心**。實際抓到過的：
   「知道」讓「我不知道」通過、「不」幾乎命中每一句中文、「別的」被「特別的」命中。
   `quiz.test.js` 有一條會拿五種空話掃過所有題目
6. `ref` 指回問題分析（數字／`'write'`／`'scene'`）。
   ⚠️ 引的是那一問的**提示**，不是正解

## ④ 程式拼圖 `palette` / `goal`

```js
palette: [ …可以拖的積木… ],
goal:    [ …正確的順序… ],
alts:    { … },      // 也算對的排法
loose:   [ … ]       // 順序不拘的幾塊
```

細節見 `03_資料格式規格.md`。

## 做完一關的檢查清單

- [ ] `scene.why` 從生活裡的東西開場，螢光筆兩三處，沒有洩漏積木答案
- [ ] `analysis.qs` 每一問都有 `keys`
- [ ] 每一問有 `pick` 或 `asks`（`asks` 至少 3 題、每題 4 選項、有 `why`）
- [ ] 一整關只有一題 `pick`
- [ ] `analysis.write` 有 `keys`、`hintText`、`sample`
- [ ] `quiz` 至少 5 題，每題有 `need`（各概念 ≥3 種說法）、`hint`、`why`、`ref`
- [ ] `node shared/tests/quiz.test.js` 和 `derive.test.js` 全綠
- [ ] 自己走一遍：**每一步都試著「亂按、亂貼、貼提示」看擋不擋得住**

> 最後那一條最重要。前面幾輪抓到的洞全部是這樣發現的：
> 回饋把答案講出來、複製提示就通關、一路按下一步就跳過整段。
> **寫完自己扮演一次「想混過去的學生」。**

## ⚠️ 改完一定要「真的畫一次」

2026-08-10：問題分析改成「一題一題」之後，整段變成**一片空白**，
而 derive／levelpage／quiz 三份測試**全綠**。

原因是 `var chosen = {}` 寫在 `draw()` 呼叫**之後** ——
`var` 會提升但**指派不會**，所以第一次畫的時候它是 `undefined`，
`askHtml` 一讀就炸，`innerHTML` 停在半路。

> **結構測試（「有沒有寫這段程式」）抓不到「畫出來沒有東西」。**
> `derive.test.js` 現在有一段會真的 render 一次、數字數、
> 走真正的點擊路徑答對一題。
>
> 加新關卡、改渲染邏輯之後，**自己開一次瀏覽器把六個步驟點完**。
> 空白是最糟的壞法 —— 沒有錯誤訊息，學生只會以為系統壞了。
