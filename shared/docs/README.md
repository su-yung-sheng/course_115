## 這套系統是什麼

八年級資訊科技課程的闖關學習網站，一套程式碼服務上下兩個學期。

```
course_115/                ← 一個 repo
├── index.html             總入口，依月份導向該學期
├── shared/             ★  共用檔，全站只有這一份
│   └── docs/           ★  你正在看的這幾份
├── 11501/                 上學期：config.js、content/、各教材頁
└── 11502/                 下學期，結構完全對稱
```

**共用檔只有一份，兩個學期用 `../shared/xxx.js` 直接引用。**
沒有副本，也就沒有「忘記同步」這回事 —— 這正是把兩個 repo 併成一個的主要理由。

## 三個最容易踩到的地雷

1. **改了 `shared/` 卻只想影響一個學期** —— 不可能，那裡是兩學期共用的。
   如果只有一個學期需要改，該動的是 `{學期}/config.js` 或 `{學期}/content/`。
2. **Colab 跑到舊版 notebook** —— 正本是 `shared/backend.ipynb`，不是雲端硬碟裡的舊副本。
   教師端的「🩺 狀態檢查」會直接告訴你跑的是哪一版。
3. **換電腦後 git hook 不見了** —— `.git/hooks/` 不會被版控，
   重新 clone 之後要再跑一次 `安裝檢查掛鉤.bat`，否則提交前的檢查不會執行。
