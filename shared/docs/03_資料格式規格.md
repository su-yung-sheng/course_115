# 03 · 資料格式規格

> Firebase 統一資料合約。所有頁面讀寫進度都必須照這份，否則 hub 與教師端會對不起來。
> **不要自己拼 Firestore 路徑**，一律走 `shared/report.js`。

---

## 1. 存放位置

- Firebase 專案：`suyungsheng-5f948`（上下學期同一個）
- Firebase 設定集中在各 repo 的 `config.js`，各頁不要自己寫死

### 1.1 分學期的集合

集合名一律 `{學期}-{用途}`，程式裡從 `CONFIG.COLLECTIONS` 取，不要寫死字串。

| 集合 | 用途 |
|---|---|
| `{學期}-progress/{學號}` | 闖關進度、星星、闖關歷程（本文件主體） |
| `{學期}-config/gradebook` | 成績簿科目與分類設定 |
| `{學期}-config/grading` | 每週成績換算設定 |
| `{學期}-config/snapshots` | 進度快照歷程 |
| `{學期}-config/schedule` | 上課日課表與停課設定 |
| `{學期}-grader/criteria` | Scratch AI 批改標準 |
| `{學期}-scratch-submissions/{id}` | AI 批改紀錄（由 Colab 後端新增） |

### 1.2 跨學期共用的集合

同一批八年級學生，這三個不分學期。從 `CONFIG.SHARED` 取。

| 集合 | 用途 | 學生可讀？ |
|---|---|---|
| `roster/{學號}` | 名冊：姓名／班級／座號 ＋ `hasCode` 旗標 | 可讀單筆 |
| `secret/{學號}` | **驗證碼本體** | ❌ 完全讀不到 |
| `session/{學號}` | 登入試探 `{ code, at }` | 只能寫，不能讀 |

> ⚠️ 2026-09-28 註：`secret`、`session` 已隨驗證碼備援在 2026-08-04 整套移除（規則也刪了）。
> 現在跨學期共用的只剩 `roster`，外加全站開關 `config`。

> 為什麼要拆成三個：驗證碼原本和姓名放在同一份名冊文件裡，而學生讀得到那份文件，
> 等於把鎖和鑰匙放在同一個抽屜。詳見 [05 安全性](05_安全性.md)。

## 2. 進度文件結構

`{學期}-progress/{學號}`：

```json
{
  "studentId": "1410112",
  "name": "王小明",
  "totalStars": 27,
  "updatedAt": 1785300000000,

  "modules": {
    "ethics":    { "status": "pass", "stars": 26, "level": 10, "total": 10,
                   "units": { "5-1": { "star": 3, "score": 92 } },
                   "score": 88, "source": "auto", "updatedAt": 1785300000000 },
    "thinking":  { "status": "in-progress", "stars": 14, "level": 7 },
    "flowchart": { "status": "in-progress", "stars": 8,  "level": 4 },
    "scratch":   { "status": "pending", "link": "https://…" },
    "logic":     { "status": "todo" },
    "search":    { "status": "todo" },
    "sort":      { "status": "todo" },
    "arduino":   { "status": "todo" }
  },

  "history": [
    { "module": "ethics", "unit": "5-2", "stars": 3, "score": 92,
      "duration": "04:12", "correct": 12, "total": 13, "at": 1785299000000 }
  ],

  "attendance": { "2026-09-01": 1785299000000 }
}
```

### 欄位說明

| 欄位 | 型別 | 說明 |
|---|---|---|
| `studentId` | string | 學號，同時也是文件 ID |
| `totalStars` | number | 各模組 `stars` 的加總，由 `REPORT` 自動維護 |
| `modules.{id}.status` | string | 見下方列舉 |
| `modules.{id}.stars` | number | 該模組星數，不超過該模組上限 |
| `modules.{id}.level` | number | 累加型模組：已完成的小關數 |
| `modules.{id}.total` | number | 累加型模組：小關總數 |
| `modules.{id}.units` | object | 各小關的最佳成績 `{ star, score }` |
| `modules.{id}.source` | string | `auto`（系統判定）或 `teacher`（老師手動） |
| `history` | array | 每次通關追加一筆，上限 400 筆，滿了丟最舊的 |
| `attendance` | object | 每天第一次登入的時間戳，同日重複進出不覆蓋 |
| `games.morningstar` | object | 晨星勇者（11501 程式設計完成十關後的獎勵遊戲）的存檔，**不算星**，見下方 |

### `games.morningstar`（2026-10-09 加）

```json
"games": { "morningstar": {
  "v": 1,
  "trained": true,                       // 新手訓練完成過（第一次不能跳過序章）
  "save": { "v": 2, "area": 2, "hp": 20, "maxHp": 20, "gold": 33, "bag": ["potion", "key", null, …],
            "equip": {…}, "quests": {…}, "talked": {…}, "kills": 40, "deaths": 1,
            "time": 900, "lv": 4, "xp": 3, "cards": {…} },   // 遊戲的 snapshot()，每章開頭一份；通關後清成 null
  "cards": { "add": 1, "ins": 1, … },    // 收集過的觀念卡（14 張，跨每一輪累積，只增不減）
  "clears": [ { "at": 1791…, "time": 1180, "lv": 6, "kills": 132, "deaths": 2,
                "gold": 41, "maxHp": 26, "cards": 14 } ],    // 最近 20 次通關
  "clearCount": 3,
  "updatedAt": 1791…
} }
```

- ⚠️ **放在 `games` 底下、不是 `modules`**：`REPORT` 的 `totalStars` 只加 `modules` 的 `stars`，所以遊戲不會變成星星。
- ⚠️ 寫入一律用 `setDoc(…, { mergeFields: ['studentId', 'games.morningstar'] })` **整欄覆寫**。
  一般的 `merge` 會把舊一輪的 `talked`／`quests` 和新的一輪合併，重新開始的人會被當成已經跟 NPC 說過話。
- 只用雲端（老師的決定）：不留 localStorage 備援。讀不到雲端就不開始遊戲。
- 安全規則**不用改**：學生本人本來就能更新自己的進度文件，而這一欄不碰作品星那幾格。
- 程式在 `shared/gamesave.js`、`11501/morningstar.html`；測試 `shared/tests/morningstar.test.js`。

### status 列舉（只有四種）

| 值 | 意思 |
|---|---|
| `todo` | 尚未開始 |
| `in-progress` | 有進度但還沒全部完成 |
| `pass` | 已通關 |
| `pending` | 已提交，等待批改 |

> ⚠️ 累加型模組**全部小關都完成**才算 `pass`。只過一關就顯示「已通關」會誤導學生。

## 3. Module ID 對照

`moduleId` 是跨學期通用的代號，**同一個代號在兩學期代表同一類學習活動**，
只是教的內容不同。各學期實際開哪幾個，看該學期 `hub.html` 的 `MODULES`。

| moduleId | 學習活動 | 星數上限 | 小關數 | 判定方式 |
|---|---|---|---|---|
| `ethics` | 章節測驗（上：資訊倫理／下：媒體與社會議題） | 30 | 10 | 自動（測驗正確率） |
| `thinking` | 運算思維挑戰 | 20 | 10 | 自動（闖關＋OCR） |
| `flowchart` | 流程圖 | 20 | 10 | 自動（判對錯） |
| `scratch` | Scratch 程式設計 | 30 | 10 | AI 批改 |
| `logic` | 邏輯挑戰 | 3 | — | 自動 |
| `search` | 線性搜尋 | 3 | — | 自動 |
| `sort` | 排序演算法 | 3 | — | 自動 |
| `arduino` | Arduino 智慧家居 | 3 | — | 自動 |

星數上限與小關數定義在 `shared/report.js` 的 `MAX` 與 `UNITS_TOTAL`，
各學期若不同可由 `config.js` 的 `UNITS_TOTAL` 覆寫。

## 4. 名冊與登入

### `roster/{學號}`

```json
{
  "studentId": "1410112",
  "cls": "801", "no": "12", "name": "王小明",
  "key": "801_12_王小明",
  "hasCode": true,
  "updatedAt": 1785300000000
}
```

- 學號格式：7 位數字、`14` 開頭
- 班級與座號由學號後四碼推算：`1410112` → 班級 `801`、座號 `12`
- `hasCode` 只是旗標，**驗證碼本體在 `secret/{學號}`**

### 登入流程

1. 學生輸入學號＋6 位數驗證碼
2. `getDoc(roster/{學號})` → 不存在就是名冊沒這個人
3. `hasCode !== true` → 首次登入，進確認畫面，自訂驗證碼後寫 `secret/{學號}`（只允許 create）
4. `hasCode === true` → 寫一筆 `session/{學號} = { code, at }`
   - 寫得進去 = 驗證通過（規則自己去比對 `secret`）
   - `permission-denied` = 驗證碼錯誤
5. 通過後 hub 把完整身分快取在 **`sessionStorage`** 的 `sid{學期}` / `me{學期}`，
   各關卡頁直接用，不必再讀名冊 —— **關閉瀏覽器就失效**

## 5. 每週成績換算

- `TERM_START`（config.js）＝第 1 週的星期一
- 週次 = 從 `TERM_START` 起算的第幾週
- 每週分數 = `0 星 → 0 分`；`有星星 → 60 + 星數 × 4`，封頂 100
- 學生端 0 星顯示 0 分（激勵）；教師端登記一律 `60 + 星數×4`（0 星＝基本分）
- 上課日依 `{學期}-config/schedule` 的課表判定，停課日不計入出席

## 6. 給檢測程式開發者

外部程式（Colab、GAS）寫回進度時：

- **一律 `merge: true`**，不要整份覆寫，否則會清掉其他模組
- `source` 填 `teacher` 或程式代號，方便日後追溯
- 星數不要超過該模組上限；`totalStars` 交給 `REPORT` 算，不要自己填
- 安全規則有防呆：**星星不可以變少、單次最多加 6 顆**（老師身分不受限）
