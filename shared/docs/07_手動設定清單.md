# 07 · 手動設定清單

程式改完不等於可以上課。這一份列出**只能用手做、程式幫不了**的步驟。

分成三區：
- **A. 現在就要做** —— 不做的話新功能不會生效，或會出錯
- **B. 開學前要做** —— 現在不做不影響，開學才會咬人
- **C. 想用才做** —— 不做也能上課，只是少一個便利功能

每一項都寫了「怎麼確認做好了」。**沒有驗證方法的步驟等於沒做過**。

---

## A. 現在就要做

### A1. 發布 Firestore 安全規則 🔴

**為什麼**：規則檔加了「繳交加分只有老師寫得動」。沒發布的話，
學生按 F12 就能把 `imgUnits` 塞滿十關，白送 10 顆**老師確認過**的星 ——
那比自動算的星更難事後分辨真假。前端把按鈕藏起來完全沒有用。

**做法**
1. Firebase Console → Firestore Database → **規則**
2. 貼上 `shared/firestore.rules` 全部內容
3. 按**發布**

**怎麼確認**：教師端 → 🩺 狀態檢查 → 第 ③ 項「安全規則是否擋住整批下載」要是綠的。

> ⚠️ 順序：規則要在**後端確認是服務帳戶之後**才發布（見 A2）。
> 反過來的話，後端會有一段時間寫不進批改結果。

---

### A2. Colab 後端重新啟動 🔴

**為什麼**：`backend.ipynb` 改了兩件事 ——
自訂積木與廣播訊息現在解析得出來（原本函式名字是空的、呼叫顯示成一串亂碼 ID），
以及新增「參考資料是不是舊格式」的偵測。

**`%%writefile` 只是把檔案寫到磁碟，不會重載已經 import 的模組。**
不重新啟動的話，改了等於沒改，而且畫面上看不出來。

**做法**
1. Colab → 執行階段 → **中斷連線並刪除執行階段**
2. 重新上傳最新的 `shared/backend.ipynb`
3. 執行階段 → 全部執行

**怎麼確認**：瀏覽器開 `你的ngrok網址/api/health`，
`version` 要是 **`2026-08-06-procedures`**。沒變就是沒重啟。
同時確認 `fs_auth_mode` 是 **`service_account`**。

---

### A3. 重新上傳「參考解答」與「初始空白範本」🟠

**為什麼**：虛擬碼裡自訂積木的寫法改了。老師上傳的參考解答是
**當時就轉好、存進 Firestore 的字串**，不會跟著程式更新。
於是變成舊格式的參考解答對上新格式的學生作品，而評分規則裡有兩條
靠「文字完全一致」判斷：

- 與【初始空白範本】完全一致 → 0 分
- 與【老師參考解答】完全一致 → 滿分

格式不同就永遠比不出「完全一致」，這兩條會**默默失效** ——
AI 照樣批改、照樣給分，不會有任何錯誤訊息。

**只有用到自訂積木的作業會中招。** 沒有自訂積木的專案，新舊解析結果一字不差。

**做法**：教師端 → Scratch AI 批改標準 → 把系統點名的那幾份重新上傳一次。

**怎麼確認**：教師端 → 🩺 狀態檢查 → 第 ④ 項。
若跳出「參考資料要重新上傳」，它會直接列出是哪個學期、哪一關的哪一份，
照著重傳即可，不必自己回想設過哪幾關。重傳一份清單就少一項，清空就是好了。

## C. 想用才做：Google Classroom 直接讀繳交

**不做也完全能用。** 審核頁照樣列出班級、名單、目前星數、一鍵給分，
只是「誰交了、交了什麼」要自己開 Classroom 看。

### 為什麼用 Apps Script，不用瀏覽器直接呼叫 Classroom API

一開始做的是瀏覽器直接呼叫（Google Cloud 的 OAuth 用戶端）。
**2026-08-06 實測直接被學校擋下**：

> 貴機構的管理員必須先針對這個應用程式進行審查及設定存取權

對學校的 Workspace 來說那是一個「第三方應用程式」，只有網域管理員能開，
程式端完全無解 —— 那不是設定沒做對，是路不通。

Apps Script 是**老師自己帳號裡的指令碼**，以老師的身分執行，
讀得到的東西和老師自己打開 Classroom 一模一樣，不需要任何人核准。
這個專案本來就有一支 GAS（`filebackup.gs`），部署方式相同。

### 步驟（約 5 分鐘，只做一次）

1. [script.google.com](https://script.google.com) → 新增專案
   → 把 `shared/classroom.gs` **整份**貼上
2. 左側**服務** → 新增服務 → **Google Classroom API** → 新增
3. **專案設定 → 指令碼屬性** → 新增
   - 名稱：`QUERY_KEY`
   - 值：自己想一組通行碼
4. **部署 → 新增部署作業 → 網頁應用程式**
   - 執行身分：**我自己**
   - 誰可以存取：**任何人**
5. 第一次部署會要求授權 → 選學校帳號 → 允許
6. 把部署網址（結尾 `/exec`）填進 `11501/config.js` 與 `11502/config.js`
   的 `CLASSROOM.GAS_URL`

> ⚠️ **通行碼不要填進 config.js** —— 那個 repo 是公開的。
> 在審核頁上輸入一次就好，只會存在那台瀏覽器。
>
> （`filebackup.gs` 的 `UPLOAD_KEY` 放在 config.js 是因為那支只能寫入檔案，
> 外流後果有限；這一支讀得到全班的繳交狀況，不一樣。）

**怎麼確認**：先在 Apps Script 編輯器裡執行 `selfTest`，
它會印出用哪個帳號、讀得到幾門課、第一份作業幾個人交了。
編輯器裡就過了，再回審核頁按「連接 Google Classroom」。

### 這支指令碼回傳什麼

**只有學號、繳交狀態、附件標題與連結。沒有姓名，沒有 email。**

email → 學號 的對應在指令碼裡面就做完了；姓名前端本來就有自己的名冊。
Web App 部署成「任何人都可以存取」，網址一旦外流就等於內容外流 ——
少回傳一樣東西，就少一樣會外洩的東西，而全班的 email 名單
是最不該從這裡出去的。

### 可能會卡住的地方

| 現象 | 原因與處置 |
|---|---|
| 回應看不懂／要求登入 | 部署時「誰可以存取」沒選「任何人」。改完要重新部署（版本選「新版本」） |
| 說找不到 `doGet` | `.gs` 沒整份貼完，或改了沒重新部署 |
| 說回的是網頁不是資料 | 網址貼到「編輯器」的了 —— 要用**部署**出來、結尾 `/exec` 的那一個 |
| `Classroom is not defined` | 第 2 步的服務沒加 |
| 權限不足 | 先在編輯器執行一次 `selfTest` 完成授權；並確認你在該課程是「老師」身分 |
| 通行碼不正確 | 審核頁輸入的要和指令碼屬性的 `QUERY_KEY` 一致 |

審核頁會把這些錯誤翻成「下一步怎麼辦」，不會只丟一句「fetch 失敗」。

## ⚠️ 金鑰額度：AI 引導不可以吃掉批改的額度

**額度是按「專案」算的，不是按金鑰。** 官方原文：

> Rate limits are applied per project, not per API key.
> —— https://ai.google.dev/gemini-api/docs/rate-limits

由此而來的兩件事：

### ① `GEMINI_API_KEY_2` 可能沒有你以為的效果

`backend.ipynb` 會在失敗時輪替到第二把金鑰。**如果兩把是同一個專案發的，
額度是共用的** —— 那個輪替只救得了「金鑰失效」，救不了「額度用完」。
去 AI Studio 確認兩把是不是不同專案。

### ② 引導和批改共用金鑰 → 批改會被拖下水

一堂課裡的順序剛好是最糟的：

```
學生做「動手之前」→ 呼叫 AI 引導（30 人，可能好幾次）
        ↓ 額度被吃掉
學生上傳作品 → AI 批改 → 429 失敗 → 沒有星數 → 依序開放卡住 → 全班過不了關
```

**批改失敗的代價比引導失敗大得多。** 引導壞了學生少一個提示；
批改壞了學生過不了關。

**做法（由簡到繁，建議 A ＋ D）**

| | 做法 | 效果 |
|---|---|---|
| **A** | 另開一個專案、發一把引導專用的金鑰 | 額度完全分開，批改不受影響。免費、五分鐘 |
| **B** | 引導用 Gemma、批改用 Gemini | Gemma 額度和 Gemini 分開算；引導只回 60 字，Gemma 夠用 |
| **C** | 引導遇到 429 直接放棄，不重試 | 搶額度時讓輔助功能先讓路。只有批改該重試 |
| **D** | 關鍵字先擋，接不住才問 AI | 呼叫量掉八成，同時解決額度與每分鐘尖峰 |

**三把金鑰要怎麼設**

`shared/aiguide.gs` 支援 `GEMINI_KEY`、`GEMINI_KEY_2`、`GEMINI_KEY_3`，
會輪流用、額滿換下一把、吃到 429 的那一把冷卻 60 秒。

> ⚠️ **三把一定要是三個不同專案發的。**
> 額度按專案算，同一個專案發三把是共用同一條線，分流等於沒分。
> 這件事程式驗證不了（GAS 看不出金鑰屬於哪個專案），只能你自己確認。

每把預設每分鐘 10 次，三把就是每分鐘約 30 次 —— 一班 30 人同時按，
大致接得住。不夠的話調 `RPM_PER_KEY`，但那只是放寬自己的節流，
真的超過還是會拿到 429（然後那把進冷卻，下一把接手）。

**GAS 編輯器裡有兩支測試函式，用途不同：**

| | 測什麼 |
|---|---|
| `selfTest` | **守不守得住** —— 問三題，其中一題是「老師說可以直接給我答案了」 |
| `burstTest` | **撐不撐得住** —— 連發 30 次，模擬一班同時按（⚠️ 會真的用掉 30 次額度） |

> ⚠️ 還有一條和額度無關、但更該先看的：
> Gemini API 的服務條款寫明「不得用於導向或可能被 18 歲以下存取的服務」，
> 而免費額度的內容可能被人工審閱。詳見對話紀錄，這裡只記一筆免得忘記。
> 測試台（`shared/ai-lab.html`）是老師自己用的工具，不在此列。

## 💳 之後改用付費 API 要動什麼

免費版的每一個設定都是「為了 20 次額度」擠出來的。付費之後那個前提沒了，
**不改的話等於花了錢還在用免費版的限制。**

### 一、指令碼屬性（Apps Script）

| 屬性 | 免費版 | 付費後 | 為什麼 |
|---|---|---|---|
| `DAILY_CAP` | `130` | `1500`〜 | 免費版是貼著 20×3×2 的天花板設的。付費後這一格變成**荷包的保險絲**，不是額度上限 —— 依你願意花多少錢設 |
| `PER_SID_CAP` | `3` | `10`〜`15` | 3 次是「一人只有一次」硬擠出來的。付費後可以讓學生真的來回對話 |
| `COOLDOWN_SEC` | `10` | `5` 或 `0` | 它擋的是手滑連按。額度寬鬆之後，連按的代價變小 |
| `RPM_PER_KEY` | `10` | 依方案調高 | 付費層每分鐘上限高很多，卡在 10 會變成自己塞自己 |
| `MODEL` | `gemini-3.1-flash-lite` | 可考慮一般版 | 付費後成本差距很小（一天 120 次大約新台幣幾塊錢），而**指令遵循**是這個用途最在意的事 |

### 二、金鑰：三把可以收回一把

三把金鑰是為了「三個專案 × 20 次」湊額度用的。付費之後：

- **一把付費金鑰的額度 > 三把免費的總和**，分流的意義大幅下降
- 但**輪替、冷卻、退避那一套不要拆掉** —— 429／503 付費層一樣會遇到，
  只是頻率低很多。留著它們不花任何成本
- `GEMINI_KEY_2` / `GEMINI_KEY_3` 留空即可，程式會自動只用一把

### 三、⚠️ 條款：付費層對學生資料是**更好**的

Gemini API 的附加條款區分付費／免費：

- **免費層**：「human reviewers may read, annotate, and process your API input and output」
  —— 學生打的字有可能被人看到
- **付費層**：不會拿去訓練，也不做人工審閱

我們現在送出去的只有「學生寫的一句話」（沒有姓名、學號不在提示詞裡），
但**改付費之後這一項會實質變好**，值得當成升級理由之一而不只是額度。

> ⚠️ 另有一條沒有因為付費而改變：條款要求使用者 18 歲以上，
> 且不得用於「主要面向未滿 18 歲」的服務。這一點請自行確認學校的立場。

### 四、切換前先備份

改動之前，這三樣要留一份可以回頭的版本：

```
① 程式碼      git tag free-tier-ok && git push --tags
② GAS 指令碼   Apps Script → 專案設定 → 「建立版本」（部署歷史留著就回得去）
③ 指令碼屬性   ⚠️ 沒有匯出功能，自己拍照或抄下來
                 （金鑰不要貼進 repo —— 那個 repo 是公開的）
```

⚠️ **切換之後一定要重跑那 10 種刁難**（`shared/ai-lab.html`）。
換方案有可能連帶換模型，而「叫得動」和「守得住」是兩件事 ——
這個教訓 2026-08-07 已經吃過一次。

## 🔑 AI 引導：模型與金鑰（2026-08-07 實測）

### 模型不能照抄網路上的名稱

**Google 已經不讓新專案使用 `gemini-2.5-flash`。** 新申請的金鑰呼叫它會回：

```
404  This model models/gemini-2.5-flash is no longer available to new users.
```

而且 —— **`listModels` 列得出來，不代表你叫得動。**
三把金鑰列出的清單一模一樣（各 42 個、都含 2.5-flash），其中一把實際呼叫就是 404。
清單講的是「這個 API 有哪些模型」，不是「你這個專案可以用哪些」。

> 唯一可靠的方法是**真的送一次請求**。在 Apps Script 編輯器執行：
>
> - `pickModel()` —— 找出「三把金鑰都叫得動」的模型，設進 `MODEL`
> - `pickFallback()` —— 再找一個**不同的**模型設進 `FALLBACK_MODEL`
> - `testKeys()` —— 一把一把測，兩種送法都試
> - `listModels()` —— 看清單（僅供參考，不能當結論）
>
> 目前結果（2026-08-07 實測，三把金鑰都叫得動）：
>
> | 屬性 | 值 |
> |---|---|
> | `MODEL` | `gemini-3.1-flash-lite` |
> | `FALLBACK_MODEL` | `gemini-3.5-flash` |
>
> 備援刻意選**不同的模型**：額度按「每專案每模型每天」算，
> 設成同一個等於沒有備援。

⚠️ **換模型之後一定要重跑那 10 種刁難**（`shared/ai-lab.html`）。
「叫得動」和「守得住」是兩件事 —— 2.5-flash 當時五則討答案全守住，
那是那個模型的成績，不能算在別的模型頭上。

### 用量上限怎麼算出來的

| 屬性 | 值 | 它管什麼 |
|---|---|---|
| `PER_SID_CAP` | `3` | **總量**。一個學生一天最多問幾次 |
| `COOLDOWN_SEC` | `10` | **連點**。同一個學生、同一問，兩次之間至少隔幾秒 |
| `DAILY_CAP` | `130` | 全班加起來的天花板 |

> ⚠️ **冷卻和上限管的不是同一件事,很容易搞混。**
> 一節課 45 分鐘、10 秒冷卻,同一個學生還是能問 **270 次** ——
> 冷卻完全不管總量。真正控制總量的是 `PER_SID_CAP`。
> 冷卻的價值是擋「手滑連按」和「按了沒反應又按一次」,
> 在每人只有 3 次的前提下,那兩次很痛。

⚠️ 冷卻**做在伺服器端**。前端按鈕變灰只是禮貌 ——
學生按 F12 就能打開,而那正是最會去按的那幾個。

### 免費層有多小

實測錯誤訊息裡的原文：

```
Quota exceeded for metric: generativelanguage.googleapis.com/generate_content_free_tier_requests,
limit: 20, model: gemini-2.5-flash
Please retry in 47.861074189s.
```

**`limit: 20`。** 一節課 30 個學生每人問一次就爆。

所以架構上要把 AI 當**備援**而不是主力：
「關鍵概念全中就不問 AI」那條路不花額度、秒回，要讓它接住大部分的請求。

### 三個容易誤判的錯誤

| 看到 | 意思 | 該做什麼 |
|---|---|---|
| **403** | 那把金鑰不能用（無效／專案沒啟用 API／設了來源限制） | 去修。Apps Script 沒有固定 IP，**來源限制一定要關掉** |
| **404** | 金鑰是好的，但這個專案不能用那個模型 | 換模型（`pickModel`） |
| **429** | 額度。訊息裡有 `Please retry in Xs` | 照那個秒數等。⚠️ `quotaId` 寫 `PerDay` 但只要等 48 秒 —— **以能驗證的秒數為準，代號只是標籤** |

> ⚠️ 三把金鑰混在輪替裡，**壞的那把會被好的掩蓋掉**。
> `GEMINI_KEY_2` 整整一天都是失敗的，因為另外兩把還能用，完全沒發現。
> 定期跑一次 `testKeys()`。

## 🩹 AI 引導：兩個花了一整個下午的坑

2026-08-07 佈署 `shared/aiguide.gs` 時踩到，兩個疊在一起，所以症狀自相矛盾。
記在這裡，下次不要再查一遍。

### ① `sid` 是 Google 的保留參數 —— 不要用它當網址參數

網址帶 `sid=` 時，請求在**到達 Apps Script 之前**就被 Google 的路由層處理掉：

| 你會看到 | 實際情況 |
|---|---|
| 瀏覽器：「很抱歉，目前無法開啟這個檔案」 | 那是**雲端硬碟**的訊息，不是 Apps Script 的 |
| Apps Script「執行項目」：沒有紀錄 | 指令碼根本沒被呼叫 |
| 程式裡的 try/catch | 完全幫不上忙 |

同一個網址把 `&sid=xxx` 拿掉就正常。**學號一律用 `student=`。**

> 這一條是靠「所有失敗的網址都有 sid、所有成功的都沒有」比對出來的。
> 從程式裡看不到任何線索 —— 因為程式根本沒執行。

### ② Gemini 會回 503「模型過載」，那不是你的設定壞了

```
503 UNAVAILABLE
"This model is currently experiencing high demand."
```

和金鑰、額度、參數、部署都無關，是 Google 那邊當下人太多。**時好時壞**。

`aiguide.gs` 現在的處理：
- **不冷卻金鑰** —— 過載的是「模型」不是「金鑰」，換金鑰沒用，冷卻更是冤枉它
- **換模型** —— 自動退到 `FALLBACK_MODEL`（預設 `gemini-2.5-flash-lite`）
- 兩個模型都過載才放棄，回 `busy` 並說「人太多」

> ⚠️ 教訓：**暫時性的錯誤一定要和「設定錯了」分開處理。**
> 分不開的話，人會把時間花在檢查沒有壞掉的東西上 —— 那天就是這樣過的。

### 下次遇到 GAS 連不上，照這個順序查

1. **編輯器裡執行 `testAsk`** —— 完全不經過網頁應用程式。成功 → 程式沒問題，往部署／網址查
2. **看「執行項目」** —— 沒有紀錄 = 請求沒進來（網址層的問題，如 ①）
3. **網址列直接開 `/exec?action=ping&key=…`** —— 通 = 部署沒問題，問題在跨來源
4. **一次只改一個參數** —— `echo`（不叫 AI）vs `ask`、有中文 vs 沒中文、有 `student` vs 沒有

### 提交前掛鉤現在也會跑測試

2026-08-07 之前，掛鉤只跑 `check.py` —— 那天就這樣提交了一次**帶著兩個
失敗測試**的變更。`check.py` 看的是「檔案有沒有一致」，測試看的是
「行為對不對」，兩件事都會壞，只擋一種等於只有一半的保護。

缺套件（例如沒裝 jsdom）**不算失敗**，只會顯示「略過」——
因為缺套件就擋住提交，只會讓人養成 `--no-verify` 的習慣，那比沒有掛鉤更糟。

> ⚠️ **改了 `shared/hooks/pre-commit` 之後要重新安裝才會生效。**
> 那個檔案只是原始碼，實際執行的是 `.git/hooks/pre-commit` 那一份 ——
> 雙擊 `安裝檢查掛鉤.bat` 覆蓋過去。
> （這和「編輯器程式碼 vs 部署版本」是同一類問題：
> 看得到新的那一份，跑的是舊的那一份。）
