# 07 · 手動設定清單

程式改完不等於可以上課。這一份列出**只能用手做、程式幫不了**的步驟。

分成三區：
- **A. 現在就要做** —— 不做的話新功能不會生效，或會出錯
- **B. 開學前要做** —— 現在不做不影響，開學才會咬人
- **C. 想用才做** —— 不做也能上課，只是少一個便利功能

每一項都寫了「怎麼確認做好了」。**沒有驗證方法的步驟等於沒做過**。

---

## A. 現在就要做

### A1. 發布 Firestore 安全規則 🔴

**為什麼**：規則檔加了「繳交加分只有老師寫得動」。沒發布的話，
學生按 F12 就能把 `imgUnits` 塞滿十關，白送 10 顆**老師確認過**的星 ——
那比自動算的星更難事後分辨真假。前端把按鈕藏起來完全沒有用。

**做法**
1. Firebase Console → Firestore Database → **規則**
2. 貼上 `shared/firestore.rules` 全部內容
3. 按**發布**

**怎麼確認**：教師端 → 🩺 狀態檢查 → 第 ③ 項「安全規則是否擋住整批下載」要是綠的。

> ⚠️ 順序：規則要在**後端確認是服務帳戶之後**才發布（見 A2）。
> 反過來的話，後端會有一段時間寫不進批改結果。

---

### A2. Colab 後端重新啟動 🔴

**為什麼**：`backend.ipynb` 改了兩件事 ——
自訂積木與廣播訊息現在解析得出來（原本函式名字是空的、呼叫顯示成一串亂碼 ID），
以及新增「參考資料是不是舊格式」的偵測。

**`%%writefile` 只是把檔案寫到磁碟，不會重載已經 import 的模組。**
不重新啟動的話，改了等於沒改，而且畫面上看不出來。

**做法**
1. Colab → 執行階段 → **中斷連線並刪除執行階段**
2. 重新上傳最新的 `shared/backend.ipynb`
3. 執行階段 → 全部執行

**怎麼確認**：瀏覽器開 `你的ngrok網址/api/health`，
`version` 要是 **`2026-08-06-procedures`**。沒變就是沒重啟。
同時確認 `fs_auth_mode` 是 **`service_account`**。

---

### A3. 重新上傳「參考解答」與「初始空白範本」🟠

**為什麼**：虛擬碼裡自訂積木的寫法改了。老師上傳的參考解答是
**當時就轉好、存進 Firestore 的字串**，不會跟著程式更新。
於是變成舊格式的參考解答對上新格式的學生作品，而評分規則裡有兩條
靠「文字完全一致」判斷：

- 與【初始空白範本】完全一致 → 0 分
- 與【老師參考解答】完全一致 → 滿分

格式不同就永遠比不出「完全一致」，這兩條會**默默失效** ——
AI 照樣批改、照樣給分，不會有任何錯誤訊息。

**只有用到自訂積木的作業會中招。** 沒有自訂積木的專案，新舊解析結果一字不差。

**做法**：教師端 → Scratch AI 批改標準 → 把系統點名的那幾份重新上傳一次。

**怎麼確認**：教師端 → 🩺 狀態檢查 → 第 ④ 項。
若跳出「參考資料要重新上傳」，它會直接列出是哪個學期、哪一關的哪一份，
照著重傳即可，不必自己回想設過哪幾關。重傳一份清單就少一項，清空就是好了。

## B. 開學前要做

### B1. 換掉測試學號 🟠

現在兩處都還是範例值 `1400000`：

| 檔案 | 行 |
|---|---|
| `shared/semester.js` | `var TEST_IDS = ['1400000'];` |
| `shared/firestore.rules` | `return sid in ['1400000'];` |

**為什麼有兩份**：安全規則沒辦法載入 JS，只能各寫一次。
只改一邊會出現「畫面進得去但進度存不了」——
`check.py` 會比對兩邊，不一致就擋下提交。

改完 `firestore.rules` 記得**重新發布**（見 A1）。

---

### B2. 確認 ngrok 網址

`SERVER_URL` 目前是 `https://flanking-snort-cyclic.ngrok-free.dev`（兩學期都是）。
換過 ngrok 網域就要同步改 `11501/config.js` 與 `11502/config.js`。

**怎麼確認**：教師端 → 🩺 狀態檢查 → 第 ① 項（後端是否在線、是不是最新版）。

---

### B3. Firebase 登入方式

**Authentication → 登入方式：只啟用 Google。**
「匿名」與「電子郵件/密碼」都要停用 —— 留著就是留一條認不出本人的路。

**Authentication → Settings → 授權網域**要有 `su-yung-sheng.github.io` 和 `localhost`。

---

### B4. Google Classroom 的作業

繳交加分是**按關**給的，所以 Classroom 上要開得出對應的作業。
建議一關一份作業（標題帶上關卡代號，例如「2-1-1 班級置物櫃 流程圖」），
審核頁的作業下拉選單才好對。

學生要交的東西：
- **流程圖圖片**：排完流程圖後複製 Mermaid 程式碼 → 貼到 mermaid.ai → 下載圖片
- **程式執行錄影**：程式跑起來的過程錄成影片

## C. 想用才做：Google Classroom 直接讀繳交

**不做也完全能用。** 審核頁照樣列出全班、照樣一鍵給分，
只是「誰交了、交了什麼」要自己開 Classroom 看。

做了的話，審核頁會直接列出繳交狀況與附件連結，點開就能看。

### 步驟（約 10 分鐘，只做一次）

1. **Google Cloud Console** → 建立專案（用 Firebase 那個也行）
2. **API 和服務 → 程式庫** → 搜尋並啟用 **Google Classroom API**
3. **OAuth 同意畫面**
   - 使用者類型：**外部**
   - 發布狀態：**測試中**
   - 測試使用者：加入**自己的學校信箱**
4. **憑證 → 建立憑證 → OAuth 用戶端 ID**
   - 應用程式類型：**網頁應用程式**
   - 已授權的 JavaScript 來源：
     ```
     https://su-yung-sheng.github.io
     http://localhost:8000
     ```
5. 把用戶端 ID 填進 **`11501/config.js` 與 `11502/config.js`** 的 `CLASSROOM.CLIENT_ID`

**怎麼確認**：教師端 → 📥 繳交審核 → 按「連接 Google Classroom」
→ 出現 Google 同意畫面 → 同意後看得到課程下拉選單。

### 為什麼是這個做法

用**老師本人在瀏覽器授權**，不是後端服務帳戶。
服務帳戶不能是 Classroom 的成員，要讀課程資料得由網域管理員開「全網域委派」，
而學校 Workspace 的管理權多半不在老師手上 —— 那條路一卡就整個做不下去。
這樣看得到的東西完全一樣，而且不需要管理員。

只要**四項唯讀權限，不含 Drive**：附件本來就帶著 Drive 檢視連結，
老師點開時已經登入 Google 就看得到；為了顯示縮圖去要敏感權限不划算，
也讓學校更可能擋下這個應用。

### 可能會卡住的地方

| 現象 | 原因與處置 |
|---|---|
| 同意畫面說「Google 尚未驗證這個應用程式」 | 正常 —— 測試中的應用程式都會。按「進階」→ 繼續 |
| **發生錯誤 400：access_not_configured** | 這個 Cloud 專案沒有啟用 Classroom API，**而且要啟用在跟用戶端 ID 同一個專案**。審核頁的錯誤訊息會直接給你指到正確專案的連結 |
| **「貴機構的管理員必須先針對這個應用程式進行審查及設定存取權」** | 學校 Workspace 擋下未經核准的第三方應用程式。**只有網域管理員能開**，見下方 |
| 訊息提到 JavaScript 來源 | 第 4 步的來源沒填對（要跟網址列完全一樣，含 https） |
| 授權視窗一閃就沒了 | 瀏覽器擋彈出視窗，允許本站彈出後再按一次 |

審核頁會把這些錯誤翻成「下一步怎麼辦」，不會只丟一串代碼。

### 學校擋掉時，要請管理員做什麼

這一關**程式端改不動**。審核頁會直接印出一段可以整段轉給資訊組的請求，
內容就是下面這些（用戶端 ID 會自動帶入）：

> 請在 Google 管理控制台將以下應用程式設為「信任」：
> 　路徑：安全性 → 存取權和資料控管 → API 控管 → 管理第三方應用程式存取權
> 　→ 設定新的應用程式 → OAuth 應用程式名稱或用戶端 ID
> 　用戶端 ID：（你的 CLASSROOM.CLIENT_ID）
> 　用途：教師本人讀取自己 Classroom 課程的作業繳交狀況，供成績登錄使用
> 　權限：全部唯讀（課程、作業繳交、名單、電子郵件），不含 Drive、不會寫入任何資料

**在管理員核准之前，審核頁照樣能用** —— 班級、名單、目前星數、一鍵給分
全都正常，只是「誰交了什麼」要自己開 Classroom 看。
這也是當初把 Classroom 做成「可有可無的一層」而不是必要條件的原因。

## 開發用（要改程式才需要）

```
npm install jsdom          只做一次
node shared/tests/blocks.test.js       積木模擬器（要 jsdom）
node shared/tests/flowchart.test.js    流程圖關卡
node shared/tests/grading.test.js      計分與加分
node shared/tests/classroom.test.js    Classroom 資料處理
python shared/check.py                 提交前檢查（commit 時自動跑）
```

換電腦或重新 clone 之後，雙擊 `安裝檢查掛鉤.bat` 把 git hook 裝回去
（hook 住在 `.git/hooks/`，不會被版控帶走）。

> ⚠️ 這個 repo **不要用 `git add -A`**。曾經因此把一把服務帳戶私鑰
> 提交並推上公開 repo（已作廢重發）。請明確列出要提交的檔案。
