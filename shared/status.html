🩺 系統狀態檢查

上課前按一下，確認 Colab 後端是最新版、兩個學期的資料沒有互相干擾。

約需 5 秒

📋 檢查不過時怎麼辦

後端離線
Colab 沒開，或閒置太久被回收。開啟 backend.ipynb，執行階段 → 全部執行。
後端是舊版
Colab 跑的不是最新 notebook。先「中斷連線並刪除執行階段」，重新上傳最新檔案再全部執行。
沒有 Gemini 金鑰
Colab 左側 🔑 Secrets 新增 GEMINI_API_KEY_1，並打開本 notebook 的存取開關。
批改標準未設定
到教師端「Scratch AI 批改標準」設定各關卡的主題與規則並存檔。
Apps Script 版本不對
改了程式碼卻沒有重新部署。Apps Script → 部署 → 管理部署 → ✏️ 編輯 → 版本選「新版本」→ 部署。 （貼了新程式碼但沿用舊版本的話， 編輯器裡測起來一切正常，/exec 卻還是舊行為。）
安全規則到底有沒有發布成功
這一頁看不出來 —— 它只驗得到「有規則在擋整批下載」，而舊版規則也會擋。 要看 Firebase Console → Firestore → 規則的最後發布時間， 以及按發布時有沒有紅字。 （規則裡只要有一個未定義的函式，整份都不會上線， 而學生端只會看到一行 permission-denied。）
OCR 那台連不上（拆成兩台時）
①b 紅的時候，第 ③ 的「截圖辨識」和第 ⑦ 一定也會紅 —— 那是同一個問題，不是三個。去開 OCR 那台的 Colab 就好。 （⚠️ 這時程式設計的批改**不受影響**，那是另一台。 另外要確認那台的 NGROK_DOMAIN 和 config.js 的 OCR_SERVER_URL 是同一個網域。）
截圖辨識變慢，或常常判不過
看第 ⑦ 張卡的結論就好，它會直接說「要不要調參數」。 （每辨識 5 張才寫一筆統計，所以要先上過一次課才有資料。 另外「關卡沒對上」的張數是分開算的 —— 那個數字高代表要改的是 關卡說明或截圖指引，不是辨識參數。）
第 ⑧ 張卡說有重複的檔案
那是同一個檔案被兩個學號傳過 —— 比對的是整份檔案的 sha256， 位元組完全相同才算，不會因為「畫面長得像」誤判。 但它是線索不是結論：也可能是同一台電腦、或幫同學代傳， 請到雲端硬碟看那幾張截圖再決定（通過的在 {學期}/thinking/， 沒過的在 {學期}/未通過/）。 （反過來也要知道：學生自己重截一次就抓不到， 所以「沒有發現重複」不等於沒有借圖。另外雜湊是後端更新之後上傳的圖 才開始記的，顯示「還沒有資料可以比對」是正常的，不是壞掉。）
程式作品那一段不一樣：.sb3 是 ZIP，在 Scratch 重存一次雜湊就完全不同，所以只抓得到「原封不動轉傳」，而且分數不會 自動調整——那一段純粹是線索，要你自己看過再決定。

這一頁只檢查「雲端」狀態。本機檔案有沒有推上 GitHub，請看 GitHub Desktop。
