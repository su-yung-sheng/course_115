### 三個關鍵改變

**(1) 檔名去掉學期前綴。**
`11501_hub.html` → `hub.html`。既然網址還沒發給學生，這一步成本最低、效益最大：兩邊檔名一致後，「上學期怎麼改的、直接套過來」才有可能自動化，`diff` 也才看得懂。

**(2) `_shared/` 是唯一可編輯的來源，`shared/` 是產物。**
改 `guard.js` 只改 `_shared/guard.js`，跑一次 `sync_shared.py`，兩個 repo 同時更新。
`check.py` 加一條規則：`shared/` 與 `_shared/` 不一致就擋下推送 —— 讓「忘記同步」變成不可能，而不是靠自律。

**(3) `config.js` 分兩層。**

`_shared/config-base.js` 放所有共通值與邏輯：

```js
window.CONFIG_BASE = {
  FIREBASE_COMMON: { apiKey:…, authDomain:…, projectId:…, storageBucket:…, messagingSenderId:… },
  SERVER_URL: 'https://flanking-snort-cyclic.ngrok-free.dev',
  BACKEND_FEATURES: ['queue','ocr_queue','models_from_secrets','term_param'],
  SEMESTERS: {
    '11501': { start:'2026-08-31', end:'2027-01-20', name:'上學期' },
    '11502': { start:'2027-02-XX', end:'2027-06-XX', name:'下學期' }   // ← 待你填
  },
  currentTerm: function(){ /* 依今天日期回傳 11501 或 11502 */ },
  build: function(term, overrides){ /* 組出 window.CONFIG，集合前綴自動生成 */ }
};
```

各 repo 的 `config.js` 縮到 20 行以內：

```js
window.CONFIG = CONFIG_BASE.build('11501', {
  FIREBASE: { appId:'…1c67c8f…', measurementId:'G-QZWM1F3FWX' },
  CLASS_PASS: '1501class',
  GAS_UPLOAD_URL: 'https://script.google.com/…',
  UNITS: [ ['2-1-1A','班級置物櫃'], … ]
});
```

集合名稱由 `term + '-progress'` 自動生成，不再各寫一份 —— 少一種打錯的機會。

## 三、關於「學期依日期自動判定」的一個提醒

你選了「依日期自動判定」，但兩個 repo 是兩個獨立網站，**所屬學期其實由網址就決定了**（打開 `course_11501/hub.html` 就是上學期）。所以日期判定實際上用在三個地方，這樣搭配才合理：

1. **`TERM_START` 自動帶入** —— 現在下學期的開學日還是從上學期複製過來沒改，每週評分與出席週次全部會算錯。改由 `SEMESTERS` 表推導後，這個 bug 不會再發生。
2. **開錯學期時提醒** —— 學生在 3 月打開上學期網站，頁面上方出現一條「現在是下學期，要前往下學期網站嗎？」的橫幅，不強制跳轉。
3. **`index.html` 入口導向** —— 若日後做一個總入口，依日期自動導到當學期網站。

如果你要的其實是「**一個網址、自動切換內容**」（也就是合併成單一站台），那就要改選第一個方案（單一 repo）。這點請你確認一下。

實測相同比例：`hub` 90%、`teacher` 88%、`thinking` 68%、`cyberethics` vs `social` 48%。

### 內容資料格式

```js
window.QUIZ_CONTENT = {
  moduleId: 'ethics',            // 進度回報用的模組代號
  color: 'blue',                 // 主色，對照《設計規範》模組代表色
  siteTitle: '…', headline: '…', // 頁面標題
  recordCollection: 'quiz_records',
  target: 10, maxWrong: 20,      // 目標連對、容錯上限

  chapters: [{
    id: 'ch1', title: '第一章 資訊倫理', color: 'blue', pdf: 'https://…',
    challenge: { id:'ch1-all', title:'…', notes:'…', questions:[…] },  // 整章挑戰，可省略
    sections: [
      { id:'1-1', title:'1-1 資訊倫理的意涵', notes:'<h4>…</h4>', questions:[{q, options, correct}] }
    ]
  }]
};
```

整章挑戰若不給 `questions`／`notes`，引擎會自動合併小節的題庫與教材 ——
下學期以後新增章節時，整章測驗不必再手動維護一份。

### 同步機制

`_shared/` 是唯一可編輯的來源，`sync_shared.py` 複製到兩個 repo 的 `shared/`：

```
python sync_shared.py           同步
python sync_shared.py --check   檢查，不一致回傳碼 1（給 push.bat 呼叫）
```

改共用檔請改 `_shared/`，不要改各 repo 裡的副本。
