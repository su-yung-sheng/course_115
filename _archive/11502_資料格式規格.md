# 學生學習進度 資料格式規格（11502-progress）

> 115 學年度第二學期 資訊科技課程 · Firebase 統一資料合約
> 最後更新：2026-07-27（由 11501 版移植）

這份文件定義**所有闖關模組、hub 儀表板、以及外部檢測程式**共用的一份資料格式。
只要大家都讀寫這份文件、依這個格式，hub 就能即時顯示每位學生的過關狀態與回饋。

## 2. 文件結構

```jsonc
{
  "studentId": "1402026",        // 學號（與文件 ID 相同）
  "name": "王小明",               // 姓名，選填，可由教師名冊帶入
  "modules": {                    // 各關卡狀態，key 為 module ID（見第 4 節）
    "ethics": {
      "status": "pass",           // 見第 5 節
      "stars": 3,                 // 0–3，選填
      "score": 90,                // 0–100，選填
      "source": "auto",           // 見第 6 節
      "updatedAt": 1753000000000  // 毫秒時間戳
    },
    "thinking":  { "status": "pass", "stars": 3, "level": 10, "source": "auto",    "updatedAt": 1753000000000 },
    "flowchart": { "status": "pass", "score": 80,             "source": "auto",    "updatedAt": 1753000000000 },
    "logic":     { "status": "todo" },
    "search":    { "status": "todo" },
    "sort":      { "status": "todo" },
    "scratch":   { "status": "pending", "link": "https://scratch.mit.edu/projects/xxx", "source": "checker" },
    "arduino":   { "status": "pending", "source": "checker" }
  },
  "categories": {                 // 選填，雷達圖用；未提供時 hub 會依 modules 自行計算
    "法律倫理": 90, "運算思維": 85, "流程圖": 80, "程式設計": 70
  },
  "history": [                    // 成績歷程，折線圖用；每次評分/過關追加一筆
    { "module": "ethics",   "stars": 3, "score": 90,  "at": 1753000000000 },
    { "module": "thinking", "stars": 3, "score": 100, "at": 1753100000000 }
  ],
  "totalStars": 9,                // 各關 stars 加總，選填（hub 也可自行計算）
  "updatedAt": 1753000000000      // 整份文件最後更新時間
}
```

寫入時請用 `setDoc(ref, {...}, { merge: true })`，只更新自己那一關，**不要覆蓋整份文件**。
歷程要追加一筆時，用 `arrayUnion(...)` 附加到 `history`，不要整個陣列覆蓋。

## 3. 欄位說明

| 欄位 | 型別 | 必填 | 說明 |
|---|---|---|---|
| `studentId` | string | ✔ | 學號 |
| `name` | string |  | 學生姓名 |
| `modules.{id}.status` | string | ✔ | 該關狀態，見第 5 節 |
| `modules.{id}.stars` | number |  | 星等；多數模組 0–3。運算思維每小關 +2（最多 20）、資訊倫理每章節 1–3 累加（約 30） |
| `modules.{id}.score` | number |  | 分數 0–100 |
| `modules.{id}.level` | number |  | 通關關卡數（如運算思維 10 關） |
| `modules.{id}.link` | string |  | 作品連結（Scratch/Arduino 用） |
| `modules.{id}.source` | string |  | 資料來源，見第 6 節 |
| `modules.{id}.updatedAt` | number |  | 該關最後更新（毫秒時間戳） |
| `categories.{類別}` | number |  | 各類別分數 0–100（雷達圖用）；未填則由 modules 計算 |
| `history[]` | array |  | 成績歷程（折線圖用），每筆 `{module, stars, score, at}` |
| `totalStars` | number |  | 星星加總 |
| `updatedAt` | number |  | 文件最後更新 |

### 4.1 類別對照（雷達圖用）

雷達圖以課程四軸為頂點。各 module 歸屬如下，hub 可由此把 module 分數彙整成類別分數（取平均）：

| 類別 | 包含 module |
|---|---|
| 法律倫理 | `ethics` |
| 運算思維 | `thinking` |
| 流程圖 | `flowchart` |
| 程式設計 | `scratch`, `arduino` |
| 演算法 | `logic`, `search`, `sort` |

- **預設做法**：不必特別寫 `categories`，hub 會依上表把 modules 的 `score` 平均成四類，即時畫雷達圖。
- **進階做法**：若要自訂類別分數，直接寫入 `categories`（見第 2 節），hub 優先採用。

### 4.1.5 星等規則（各模組上限不同）

| 模組 | 星等規則 | 上限 |
|---|---|---|
| `thinking` 運算思維 | 每通過一小關 +2 星（10 小關累加） | 20 |
| `ethics` 資訊倫理 | 每章節依最佳正確率給 1–3 星（100%→3、≥80%→2、其餘→1），約 10 章節累加 | ~30 |
| `flowchart` 流程圖 | 10 關（對應 10 個程式單元），每關排對流程圖 +2 星累加 | 20 |
| `scratch` 程式設計 | 10 關，每關程式依完成度 2–3 星（由外部檢測程式評分） | 30 |
| `logic` / `search` / `sort` / `arduino` | 依表現分級 1–3（各自規則待各模組接回報時定義） | 3 |

hub 以 `MODULES[].maxStars` 記各模組上限（thinking=20、ethics=30、flowchart=20、scratch=30、其餘=3），累積星星總分母 = 各上限加總。卡片顯示：上限 ≤3 用 ★☆ 圖示，>3 用「⭐ N 星」數字。

**流程圖回報**：`11502_flowchart.html` 完成一關寫入 `modules.flowchart`，並用 `arrayUnion` 把單元 id 加入 `modules.flowchart.units`，`stars = units.length × 2`、`level = units.length`。（本學期尚未建立共用參考說明頁）。

### 4.2 成績歷程（折線圖用）

每次評分或過關時，往 `history` **追加一筆**（不要覆蓋）：

```js
import { arrayUnion } from "firebase/firestore";
await setDoc(ref, {
  history: arrayUnion({ module: "thinking", stars: 3, score: 100, at: Date.now() })
}, { merge: true });
```

hub 讀 `history`、依 `at` 排序即可畫出每位學生的成績歷程折線圖。
資料量大時也可改用子集合 `11502-progress/{學號}/history/{自動ID}`，欄位相同。

## 7. 給檢測程式開發者

你的檢測程式負責 `scratch` 與 `arduino` 兩關。判定完成後，請寫入同一份文件：

```js
// 以 Firebase Web SDK 為例
import { getFirestore, doc, setDoc, arrayUnion } from "firebase/firestore";

const db = getFirestore(app);
const ref = doc(db, "11502-progress", studentId);
const now = Date.now();

await setDoc(ref, {
  studentId,
  modules: {
    scratch: {
      status: "pass",          // 或 "pending" / "todo"
      stars: 3,
      score: 95,
      link: "https://scratch.mit.edu/projects/xxx",
      source: "checker",
      updatedAt: now
    }
  },
  history: arrayUnion({ module: "scratch", stars: 3, score: 95, at: now }), // 追加歷程
  updatedAt: now
}, { merge: true });          // ★ 一定要 merge，避免蓋掉其他關卡
```

重點：
1. 集合名稱 `11502-progress`、module ID 必須與本文件一致。
2. **一定要用 `{ merge: true }`**，只更新 `scratch` 或 `arduino`，不可覆蓋整份文件。
3. 歷程用 `arrayUnion(...)` **追加**到 `history`，不要整個陣列覆蓋。
4. `source` 請填 `"checker"`，方便追蹤資料來源。
5. 寫入後 hub 會透過 `onSnapshot` 即時亮燈，無需通知學生重整頁面。

## 7.5 學生名冊（11502-roster）— 身分對照

因為闖關模組（thinking、social）用 **班級+座號+姓名** 辨識學生，而 hub／`11502-progress` 用 **學號**，需要一份名冊做對照。由教師端「名冊管理」維護。

```
11502-roster/{學號}
├─ studentId: "1401001"       // 學號（= 文件 ID）
├─ cls: "801"                 // 班級（801–812）
├─ no:  "1"                   // 座號
├─ name: "王小明"             // 姓名
├─ code: "482913"             // 6 位登入驗證碼（學生首次登入自設，初始為空）
├─ key: "801_1_王小明"        // = `${cls}_${no}_${name}`，供模組反查身分
└─ updatedAt
```

- 教師端可單筆新增／刪除／清除密碼，或用「批次匯入」貼上 `學號,班級,座號,姓名[,驗證碼]` 一次匯入（驗證碼通常留空，重複匯入會保留原有碼）。
- **驗證碼由學生首次登入自設**（名冊初始為空）；教師在名冊看得到學生設的碼，若學生忘記可「清除密碼」讓其重設。

### 7.6 全站登入（學號＋驗證碼 SSO，首次自設）

所有學生頁面（hub、thinking、social）統一用**學號＋驗證碼**登入，登入畫面含「學號 / 姓名（首次）/ 驗證碼」三欄：

1. 讀 `11502-roster/{學號}`；查無 → 提示「找不到學號，請找老師」。
2. **首次登入**（名冊 `code` 為空）：需輸入與名冊相符的**姓名**驗身，並自訂 6 位驗證碼，寫回 `code`。
3. **之後登入**（已有 `code`）：比對驗證碼，不符 → 提示「驗證碼錯誤」。
4. 通過後把學號存進 `localStorage['sid11502']`。
5. **SSO**：其他頁面偵測到 `sid11502` 就自動登入（信任 localStorage，不再要求姓名或驗證碼），並用名冊帶出班級／座號／姓名。登出才清除。

> 模組內部仍以 `班級_座號_姓名`（= `key`）記錄自己的資料，這些欄位改由名冊帶出，原邏輯不變。

## 7.7 教師端資料結構（Firebase 化，取代 Apps Script）

策略：**只換資料來源、保留現有畫面**。Firebase 讀出來後組成與原本相同的記憶體形狀（`spreadsheetData / subjects / customMapping / progressHistory`），餵給現有 UI，因此手動評分、個別學生視窗、進度分析（圖表／快照）都照舊。

**登入**：Firebase Authentication（教師 Email＋密碼），已完成。

**成績簿設定** `11502-config/gradebook`
```jsonc
{
  "subjects": [ { "key": "subj_2", "label": "第1章 語文常識", "index": 2 }, … ],
  "customMapping": { "categories": ["第一單元","第二單元"], "taskMap": { "subj_2": "第一單元" } }
}
```

**各生成績** `11502-grades/{學號}`
```jsonc
{ "studentId": "1401001", "cls": "801", "scores": { "subj_2": 3, "subj_3": 2 }, "updatedAt": 0 }
```

**進度快照** `11502-config/snapshots`
```jsonc
{ "history": [ { "date": "…", "…": "…" } ] }   // = 原 progressHistory
```

對應關係：
- 學生名單、姓名、班級 → 由 `11502-roster` 帶入（已建）。
- 全班成績表 = 對每位 roster 學生，合併其 `11502-grades` 分數，依 `cls` 分組成 `spreadsheetData`。
- 自動檢查結果（`11502-progress`）可選擇性映射成某些 subject 顯示（模組 → 科目）。
- 儲存：手動改分 → 寫 `11502-grades/{學號}`；分類設定 → `11502-config/gradebook`；快照 → `11502-config/snapshots`。

> 實作方式：把 `fetchGoogleSheetData()` 換成讀上述集合、`saveGrades/saveSettings/saveHistory` 換成寫上述集合，其餘 UI 不動。

## 7.8 每週成績換算

依教師需求：**計分依據＝完成關卡數；只算當週新完成；週次依課程週次；輸出螢幕表格＋CSV**。

**設定** `11502-config/grading`
```jsonc
{
  "semesterStart": "2025-09-01",  // 學期第 1 週的起始日（老師設定）
  "pointsPerTask": 20,            // 每完成一關的分數（老師可調，預設值示意）
  "weekCount": 20                 // 學期週數（選填）
}
```

**計算方式**
1. 週次：`週次 = floor((完成日 − semesterStart) / 7) + 1`。
2. 當週新完成：掃 `11502-progress/{學號}.history`，取 `at` 落在該週區間、且該筆代表過關的紀錄，**計數**（同一關同週只計一次）。
3. 當週分數：`當週完成關卡數 × pointsPerTask`（可設上限，例如封頂 100）。

**呈現與輸出**
- 螢幕表格：列＝學生（座號/姓名），欄＝週次或「選定某週」，值＝當週分數。
- CSV：同表格內容匯出，可匯入校務系統／Excel。
- 資料來源全部 Firebase（`11502-roster` 學生、`11502-progress.history` 完成紀錄、`11502-config/grading` 規則）。

> `pointsPerTask`、`semesterStart` 屬「設定」，老師可在教師端調整；換算與呈現分離，日後改報表樣式不動計算邏輯。

## 8. 安全性提醒（待辦）

目前資料放在公開集合 `11502-progress`、匿名登入、以學號為 key，代表**知道別人學號就能讀寫他人進度**。
正式上線前建議設定 Firestore 安全規則，限制學生只能寫入自己的文件。此項列為後續資安階段處理。
